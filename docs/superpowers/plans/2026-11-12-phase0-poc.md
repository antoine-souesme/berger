# Berger phase 0 (POC) — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** une fenêtre Electron branchée sur herdr-core qui montre les spaces, terminaux et états des agents en direct, permet de taper dans un terminal partagé avec Herdr, et ouvre un fichier du space dans Monaco avec `cmd-f` et `cmd-s`.

**Architecture:** le processus principal lance `hc connect` (une connexion pour les requêtes et les fichiers, une pour les événements, une tramée par terminal ouvert) et passe tout à la fenêtre par IPC via le preload. Les règles (arbre des spaces, états, dossier, filtre de fichiers, décodage des messages) sont des modules purs dans `src/shared/`, testés avec vitest. La fenêtre est en TypeScript sans framework : une colonne de gauche, un terminal xterm.js, un éditeur Monaco.

**Tech Stack:** Electron, electron-vite (modèle vanilla TS), TypeScript, vitest, `@xterm/xterm` + `@xterm/addon-fit`, `monaco-editor`, `node-pty` (seulement en cas de repli, tâche 4). Node 24.

**Spec:** `docs/superpowers/specs/2026-11-12-phase0-poc-design.md`

## Global Constraints

- Ne jamais tuer, retirer, renommer ni écrire dans un terminal ou un document du core d'Antoine : pas de `terminal.kill`, `terminal.rm`, `terminal.label`, `doc.set`, `terminal.send` depuis le code ni pendant les tests. Seules les touches tapées par Antoine partent vers un terminal.
- Tests manuels : lancer ses propres terminaux (`hc run --bg --name berger-test-… zsh`), sans étiquettes `herdr.*`, puis `hc kill` + `hc rm` sur eux seuls.
- Ne rien modifier dans `~/.config/herdr-app/` ni dans `~/dev/playground/herdr-app-mod/`.
- Textes de l'interface en français, avec les accents.
- Code repris d'ailleurs : source et licence dans `COPIES.md`.
- Machine locale seulement (pas de `on`).
- Avant de dire qu'une tâche marche, lancer l'app (`npm run dev`) et la regarder.
- Protocole : JSON-RPC 2.0, un message par ligne ; toujours commencer par `hello` avec `{"generation":1}`.

## Review Focus

1. Le core redémarre ou `hc connect` meurt : la colonne affiche « Déconnecté de herdr-core », l'app ne plante pas et se rebranche toute seule (tâche 2).
2. Le terminal ouvert se termine ou est perdu : la vue affiche « Terminal terminé » au lieu de se figer ou de planter (tâche 4).
3. Antoine crée, renomme ou supprime un space dans Herdr : la colonne suit sans relancer Berger, grâce à l'événement `doc` (tâche 3).
4. Un agent modifie le fichier ouvert pendant qu'Antoine l'édite : `cmd-s` prévient avant d'écraser (tâche 5).
5. Un fichier binaire ou un dossier énorme : message clair (`not_text`), liste plafonnée à 5 000 fichiers sans dossiers lourds (tâche 5).

**Interfaces:**

- Produces (dans `src/shared/spaces.ts`) :
  - `type TerminalCore` = champs utilisés de `Terminal` du schéma : `address, name, title, cwd, state, status?: {state: string} | null, foreground?: {cwd: string} | null, labels`.
  - `type VueTerminal = { adresse: string; libelle: string; etat: string }`

  - `construireVue(doc: unknown, terminaux: TerminalCore[]): { spaces: VueSpace[]; autres: VueTerminal[] }` — nom = `space.name` s'il n'est pas vide, sinon le dernier segment du dossier ; libellé d'un terminal = `name` ?? `title` ?? `address` ; une adresse de l'arbre absente des terminaux vivants est sautée ; `autres` = les terminaux vivants rangés dans aucun space.

### Task 5: Éditeur Monaco sur un fichier du space

- Test: `tests/fichiers.test.ts`

**Interfaces:**
- Consumes: `Hc.requete` (tâche 2), `VueSpace.dossier` et le clic sur un space (tâche 3).
- Produces (dans `src/shared/fichiers.ts`) :
  - `DOSSIERS_IGNORES = [".git", "node_modules", "out", "dist", "build", ".next", "target", ".venv"]`
  - `LIMITE_FICHIERS = 5000`
  - `filtrerFichiers(chemins: string[], requete: string): string[]` — chemins relatifs ; requête vide → tous ; sinon chaque lettre de la requête dans l'ordre, sans tenir compte de la casse ; ceux dont le nom de fichier contient la requête d'un bloc passent en premier.
  - `langageDe(chemin: string): string` — identifiant Monaco depuis l'extension (`.md`→`markdown`, `.ts`→`typescript`, `.js`/`.mjs`→`javascript`, `.json`→`json`, `.css`, `.html`, `.py`, `.rs`, `.sh`→`shell`, `.yaml`/`.yml`→`yaml`, autre→`plaintext`).
- Côté main (`src/main/fichiers.ts`) : `listerFichiers(dossier): Promise<string[]>` en Node (`fs.readdir` récursif, `DOSSIERS_IGNORES` sautés, arrêt à `LIMITE_FICHIERS`) ; `lire(chemin)` = `file.read {path}` → `text` ; `ecrire(chemin, texte)` = `file.write {path, data: base64(utf8)}`. IPC : `berger:lister`, `berger:lire`, `berger:ecrire`.
- Côté fenêtre : clic sur un space → `choix-fichier.ts` affiche, au-dessus de l'éditeur, un champ « Filtrer les fichiers… » et la liste filtrée (200 premières lignes) ; Entrée ou clic ouvre le fichier dans Monaco (`editeur.ts`) ; `cmd-f` = recherche intégrée de Monaco ; `cmd-s` = relire le fichier sur le disque, s'il diffère du texte chargé demander « Le fichier a changé sur le disque depuis son ouverture. Enregistrer quand même ? » (Enregistrer / Annuler), puis `berger:ecrire` et un court message « Enregistré » ; `not_text` → « Ce fichier n'est pas du texte. » ; thème `antoine-monokai` (lu dans `~/dev/playground/herdr-app-mod` ou `~/.config/herdr-app/themes`, couleurs recopiées, source notée dans `COPIES.md`) seulement si moins de 30 min, sinon `vs-dark`.
